# Решения на потом

Технологии и механизмы, которые обсуждались и осознанно не взяты сейчас. У каждой записи —
наблюдаемый триггер переключения (число или факт, а не «когда понадобится»).

## Признак «узлу нужен аккаунт» — из каталога, а не списком на фронте

**Что запрошено.** Фронт должен знать, каким узлам аккаунт обязателен, чтобы предупредить
оператора до запуска.

**Что делаем вместо этого сейчас.** Константа `ACCOUNT_REQUIRED_KEYS` в
`frontend/src/canvas/accountScope.ts` — три ключа списком, у каждого комментарий с файлом и
строкой узла-источника.

**Почему отложено.** Узлов с обязательным аккаунтом ровно три: `logic.get_my_lots`
(`get_my_lots.py:44`), `market.relist` (`relist.py:124`), `forum.bump_thread`
(`bump_thread.py:56`). Остальные имеют путь `*_via_pool` и работают без пина. Правка
контракта каталога и схемы узла ради трёх строк дороже самих трёх строк.

**Триггер переключения.** Любое из двух:
- узлов с обязательным аккаунтом становится **больше пяти**;
- узлы начинает добавлять кто-то, кроме этого репозитория (плагины, сторонние каталоги) —
  тогда список на фронте перестаёт быть полным по построению.

**Цена перехода тогда.** Поле `requires_account: bool` в DTO каталога, заполнение у всех узлов,
чтение на фронте вместо константы. Оценка — полдня, миграций не требует: каталог отдаётся
из кода, а не из БД.

**Что дёшево сделать сейчас, чтобы дверь осталась открытой.** Держать проверку в одном месте
(`isInsideAccountLoop` + `ACCOUNT_REQUIRED_KEYS` в одном модуле), не размазывая условие по
компонентам. Абстракцию с одной реализацией не заводить: когда придёт флаг, меняется тело
одной функции.
